## Specific guidance
- Playable game: one click to play; state the engineering behind it. No data that games help or hurt (opinion only).
- NDA/client work: describe function not client, use published figures, link published case studies. https://www.randstad.com.au/career-advice/career-tips/how-to-showcase-engineering-project-works-under-nda/ · https://www.techinterview.org/post/3233474609/engineering-resume-experience-section-nda/
- Unannounced project: "coming soon" placeholders are advised against (signal no follow-through; opinion). Safer: a dated "in progress" entry describing the technical problem and your role, no product details.

## The bar (checklist)
- [ ] First screen: name, role, one-line pitch, links to resume PDF, GitHub, LinkedIn, email.
- [ ] Each project: problem, my role, stack, one or two numbers, live link, code link — readable in under a minute.
- [ ] Featured case studies (Ship, OpenEMR co-pilot, Silent Flow) with before/after metrics — the gap no example fills.
- [ ] KeyBlaster: "Play now" one click, loads fast, works on mobile or says it needs a keyboard; short "how it's built".
- [ ] Two Aim case studies as cards linking to aimconsulting.com, client described by function.
- [ ] Takavay: dated "In progress" card with the engineering problem space, no product details, no "coming soon".
- [ ] Visible dates everywhere; nothing broken (check every link before launch).
- [ ] Core Web Vitals green on mobile; accessible (WCAG AA); no slow intro animations.
- [ ] Resume and site say the same things.
